Соглашения фронтенда для проекта комментариев
Структура

resources/js/
├── app.js                    # точка входа: createApp(App).mount('#app')
├── App.vue                   # страница: таблица, сортировка, пагинация, форма
├── bootstrap.js, echo.js     # Axios и Laravel Echo (Reverb)
└── components/
    ├── CommentForm.vue       # форма добавления/ответа, валидация, reCAPTCHA
    └── CommentNode.vue       # рекурсивный компонент ветки ответов

Новый компонент кладём в components/. Повторяющуюся разметку и логику выносим в компонент или функцию (DRY), без лишней сложности (KISS).
Правила Vue

    Vue 3, Composition API, <script setup>. Options API не используем.
    Рекурсивные ветки через компонент, ссылающийся на себя (CommentNode). Глубина не ограничена.
    Состояния интерфейса: загрузка, пустой список, ошибка, успех. Кнопка отправки блокируется на время запроса.
    Каждому v-for задаём стабильный :key (id записи, не индекс).

Безопасность

    v-html только для поля text комментария: сервер уже очистил его CommentSanitizer. Все остальные данные выводим через {{ }}.
    Внешние ссылки открываем с rel="nofollow noopener".

Формы и валидация

Клиентская валидация зеркалит серверную и никогда её не заменяет:

    User Name: обязательное, только [A-Za-z0-9_-] (латиница, цифры, подчёркивание, дефис), минимум две латинские буквы в любом месте.
    E-mail: обязательное, формат e-mail.
    Home Page: необязательное, только http:// или https://.
    Text: обязательное, разрешены <a href title>, <code>, <i>, <strong>, теги должны быть закрыты и правильно вложены. Остальные теги сервер экранирует.
    CAPTCHA: Google reCAPTCHA, токен отправляется в поле captcha, после отправки виджет сбрасывается.

Ошибки сервера (422) показываем у соответствующих полей. Ошибки 429 и 5xx показываем общим сообщением.

После успешной отправки (ответ 2xx):

    Форма открыта в модальном окне BaseModal. Окно закрывается с анимацией (Transition), форма полностью очищается.
    Над списком на 5 секунд показываем сообщение «Your comment has been sent» (role="status").
    Ответ 5xx не считается успехом, даже если запись успела сохраниться: окно остаётся открытым с общей ошибкой. Если так происходит, причину ищем в storage/logs/laravel.log, а не маскируем на фронтенде.
    Ответ 419 (истекла сессия) обрабатывает перехватчик axios в bootstrap.js: один раз получает новый CSRF-токен через HEAD / и повторяет запрос. В компонентах 419 отдельно не обрабатываем.

Модальные окна и анимации

    Модальные окна только через BaseModal (Teleport to="body"): закрытие по Esc, по клику на фон и по кнопке ×, блокировка прокрутки страницы, фокус в окно при открытии и обратно на кнопку при закрытии, на телефоне на всю ширину.
    Анимации через Transition и TransitionGroup, наборы классов берём из resources/js/transitions.js. Новые элементы списка появляются через TransitionGroup с :key по id.
    Длительность анимаций задаём только классами motion-safe:, чтобы при prefers-reduced-motion анимаций не было.
    Библиотеки для модалок и анимаций не добавляем.
Стили и UX

    Только Tailwind-классы. Vuetify и другие UI-библиотеки не добавляем (конфликт со стилями Tailwind).
    Mobile-first, без горизонтальной прокрутки страницы. Таблица внутри overflow-x-auto.
    Доступность: у полей label, у кнопок понятный текст, фокус виден, цвет не единственный носитель смысла.
    Если классы Tailwind не применяются, проверить @source '../**/*.vue'; в resources/css/app.css.

WebSocket (Echo)

    Канал comments, событие .comment.created (точка в начале, потому что событие имеет broadcastAs).
    Сигнал только сообщает об изменении, данные заново запрашиваем через GET /comments.
    Страница должна работать и без Echo (window.Echo?.), просто без живых обновлений.
    При уходе со страницы отписываемся: window.Echo?.leave('comments').

Vite и Docker

    Порт задаётся VITE_PORT, проброс в compose симметричный (порт:порт).
    Опрос файлов (usePolling) включается только VITE_USE_POLLING=true, по умолчанию он выключен.
    vite.config.js и порты без необходимости не меняем. Изменения VITE_* требуют перезапуска node.

Проверка перед завершением

```bash

docker compose run --rm -e npm_config_cache=/tmp/.npm node npm run build
docker compose logs --tail=30 node

Сборка должна пройти без ошибок. Визуальную проверку в браузере выполняет человек: список, форма, ответ на комментарий, сортировка, пагинация, мобильная ширина.
