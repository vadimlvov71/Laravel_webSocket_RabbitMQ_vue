# Соглашения документации

Документация на русском и пишется для разработчиков, которые видят проект впервые. Код, команды, имена файлов и классов не переводятся.

## Устройство

| Что | Где |
|---|---|
| Входная точка | `README.md`: бейджи, «Содержание», «Документация», разделы по функциям |
| Отдельные страницы | `docs/wiki/<Name>.md`. Имя на английском в PascalCase: оно же станет названием страницы на вкладке Wiki (`Scaling.md` → «Scaling») |
| Картинки | `docs/images/<kebab-case>.png`. Не в `public/`: оттуда всё раздаёт веб-сервер |
| Документация API | генерируется Scramble (`/docs/api`), вручную не пишется (см. `api-conventions`) |

## README.md

1. **Порядок:** логотип и бейджи → `## Содержание` → `## Документация` → разделы.
2. **Новый раздел `##`** — сразу пункт в «Содержании». Якорь по правилам GitHub: строчные буквы, пробелы → `-`, знаки препинания удаляются, кириллица остаётся. Примеры:
   - `## Поиск (Elasticsearch)` → `#поиск-elasticsearch`;
   - `## CI/CD` → `#cicd`;
   - `## Демо: живые обновления через WebSocket` → `#демо-живые-обновления-через-websocket`.
3. **Новая страница в `docs/wiki/`** — строка в таблице «Документация»: эмодзи, ссылка, одно предложение «о чём».
4. **Бейджи** показывают только этот репозиторий. Бейдж CI: `actions/workflows/ci.yml/badge.svg`. Бейджи чужих проектов (Laravel framework, packagist) не добавлять.
5. **Раздел функции** — коротко: зачем, команда запуска в блоке `bash`, 3–5 пунктов «как устроено» со ссылками на код. Подробности — в отдельную страницу `docs/wiki/`.

## Ссылки

| Откуда → куда | Как |
|---|---|
| README или `docs/` → файл репозитория | **относительный** путь: `[CI](.github/workflows/ci.yml)`, `[Масштабирование](docs/wiki/Scaling.md)`. Работает в любой ветке и в форках |
| `docs/wiki/*` → код | **абсолютный** URL на основную ветку `main`: `https://github.com/vadimlvov71/Laravel_webSocket_RabbitMQ_vue/blob/main/<path>`. Вкладка Wiki — отдельный репозиторий, относительные пути там не работают |
| Между страницами wiki | `[Scaling](Scaling)` на вкладке Wiki; в репозитории — относительный `Scaling.md` |
| Локальный проект | `http://localhost:8086/...` только с пометкой «при запущенном проекте» |

Не использовать `blob/master` (основная ветка `main`) и ссылки `blob/...` на картинки.

## Картинки

```markdown
![Что на картинке и какой вывод из неё следует](docs/images/ci-pipeline.png)
```

- Путь относительный, файл в `docs/images/`, имя в kebab-case по содержанию (не `Untitled.png`, не `image.png`).
- Alt-текст описывает, что видно на картинке: его читают скринридеры и он показывается, если картинка не загрузилась. Перед тем как писать alt, открыть картинку и проверить.
- Скриншоты обрезать до нужной области. На скриншоте не должно быть токенов, ключей, `.env`, личных email.
- Схемы лучше делать на Mermaid (блок ` ```mermaid `): GitHub отрисует их сам, и их можно править как текст.

## Страница docs/wiki

- Начинается с `# Заголовок` и одного абзаца: о чём страница и главный вывод.
- Длинная страница (больше 4 разделов) — с оглавлением.
- Таблицы для сравнений и списков «что → где», блоки кода с языком (`bash`, `php`, `sql`, `yaml`).
- Различать сделанное и план: «сейчас в коде…» против «нужно / предлагается…».

## Публикация на вкладку Wiki

Источник правды — `docs/wiki/` в основном репозитории (ревью через pull request). На вкладку Wiki страницы копируются:

```bash
# один раз: создать в веб-интерфейсе любую первую страницу Wiki, иначе репозитория ещё нет
git clone https://github.com/vadimlvov71/Laravel_webSocket_RabbitMQ_vue.wiki.git ../dzencode.wiki
cp docs/wiki/*.md ../dzencode.wiki/
cd ../dzencode.wiki && git add . && git commit -m "Sync docs/wiki" && git push
```

Картинки, на которые ссылается страница wiki, указывать абсолютным URL `https://raw.githubusercontent.com/vadimlvov71/Laravel_webSocket_RabbitMQ_vue/main/docs/images/<file>`.

Публикация (push в `.wiki.git`, коммиты) — только по просьбе пользователя.

## Проверка перед завершением

1. Каждая относительная ссылка ведёт на существующий файл:
   ```bash
   grep -oE '\]\([^)#:]+\)' README.md docs/wiki/*.md | sed -E 's/.*\]\(([^)]+)\)/\1/' | sort -u | while read -r f; do [ -e "$f" ] || echo "нет файла: $f"; done
   ```
2. Нет `blob/master` и абсолютных ссылок на файлы репозитория в README: `grep -n 'blob/master' README.md docs -r`.
3. Каждый `##` README есть в «Содержании», каждая страница `docs/wiki/` — в таблице «Документация».
4. После пуша открыть README на GitHub и проверить, что картинки и схемы отображаются, якоря переходят.
